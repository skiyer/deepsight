## 1. 执行摘要

本文档描述 DeepSight 智能代码分析平台的技术架构设计。系统采用 **全栈 TypeScript** 技术栈，以 **Claude Code Agent SDK** 为核心分析引擎，通过 **HTTP + SSE** 协议实现流式交互，支持 VS Code 插件和 CI 系统两种接入模式。

---

## 2. 架构目标与约束

### 2.1 核心目标

| 目标 | 描述 | 优先级 |
|------|------|--------|
| 极速开发 | 一周内完成 MVP，两周内可发布 | P0 |
| 流式体验 | 打字机效果，思考过程可视化 | P0 |
| 双端复用 | VS Code 与 CI 共用同一分析引擎 | P0 |
| 类型安全 | 前后端共享类型定义，编译期捕获错误 | P1 |

### 2.2 技术约束

- 前后端统一使用 TypeScript
- 采用 Claude Code Agent SDK（非直接 API 调用）
- 使用标准 HTTP 协议，便于调试和部署
- 支持云端 VS Code（Codespaces/vscode.dev）场景

## 5. Agent 集成设计

### 5.1 Agent SDK 封装策略

不直接调用 Claude API，而是通过 Agent SDK 获得以下能力：

| 能力 | 直接 API | Agent SDK | 价值 |
|------|----------|-----------|------|
| 单轮对话 | ✅ | ✅ | - |
| 多轮推理 | ❌ 需自行实现 | ✅ 内置 | 复杂问题拆解 |
| 工具调用 | ❌ 需自行编排 | ✅ 自动循环 | 文件读写、代码执行 |
| 上下文管理 | ❌ 需自行维护 | ✅ 内置 | 长会话记忆 |
| 流式思考 | 部分 | ✅ 完整 | 思考过程可见 |

### 5.2 自定义工具注册

为 Agent 注册以下专用工具：

| 工具名称 | 功能 | 输入 | 输出 |
|----------|------|------|------|
| `read_file` | 读取项目文件 | 文件路径 | 文件内容 |
| `list_directory` | 列出目录结构 | 目录路径 | 文件列表 |
| `search_symbol` | 查找符号定义 | 符号名称 | 位置列表 |
| `get_references` | 获取引用关系 | 符号名称 | 引用位置 |
| `parse_ast` | 解析语法树 | 代码片段 | AST JSON |
| `run_linter` | 执行静态检查 | 文件路径 | 问题列表 |

### 5.3 Agent 事件流映射

将 Agent SDK 的内部事件转换为 SSE 事件：

| Agent SDK 事件 | SSE 事件类型 | 前端处理 |
|----------------|--------------|----------|
| `agent.thinking` | `thinking` | 显示思考气泡 |
| `tool.start` | `tool_use` | 显示工具调用卡片 |
| `tool.complete` | `tool_result` | 更新工具结果 |
| `message.delta` | `chunk` | 追加文本（打字机） |
| `agent.complete` | `done` | 渲染最终结果 |
| `agent.error` | `error` | 显示错误提示 |

## 6. 通信协议设计

### 6.1 API 端点定义

| 方法 | 路径 | 描述 | 响应类型 |
|------|------|------|----------|
| `GET` | `/health` | 健康检查 | JSON |
| `POST` | `/analyze` | 启动分析（流式） | SSE |
| `POST` | `/analyze/batch` | 批量分析（CI用） | JSON |
| `GET` | `/session/:id` | 获取会话状态 | JSON |
| `DELETE` | `/session/:id` | 终止会话 | JSON |

### 6.2 SSE 事件格式

```
event: <event_type>
data: <json_payload>

```

事件类型与载荷结构：

| 事件类型 | 载荷字段 | 说明 |
|----------|----------|------|
| `thinking` | `{ content: string }` | Agent 当前思考内容 |
| `tool_use` | `{ tool: string, input: object }` | 工具调用开始 |
| `tool_result` | `{ tool: string, output: object }` | 工具调用结果 |
| `chunk` | `{ content: string }` | 增量文本输出 |
| `done` | `{ summary: object }` | 分析完成，包含结构化结果 |
| `error` | `{ code: string, message: string }` | 错误信息 |

### 6.3 请求参数结构

**分析请求：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `file` | string | ✅ | 目标文件路径 |
| `code` | string | ✅ | 文件完整内容 |
| `line` | number | ✅ | 焦点行号 |
| `mode` | enum | ✅ | `explain` 或 `audit` |
| `scope` | enum | ❌ | `file` 或 `project`，默认 `file` |
| `language` | string | ❌ | 输出语言，默认 `zh-CN` |

## 9. 技术选型

| 类别 | 选型 | 理由 |
|------|------|------|
| 运行时 | Bun | 启动快、原生 TS、内置测试 |
| Web 框架 | Hono | 轻量、类型安全、SSE 原生支持 |
| Agent SDK | @anthropic-ai/sdk | 官方 SDK，Agent 模式支持 |
| AST 解析 | tree-sitter (WASM) | 多语言支持、高性能 |
| 包管理 | pnpm | Monorepo 友好、磁盘效率高 |
| 类型共享 | TypeScript Project References | 编译期类型检查 |
| CI/CD | GitHub Actions | 与目标场景天然集成 |
| 容器 | Docker (Bun base image) | CI 和 SaaS 部署统一 |

## 11. 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| Agent SDK 不稳定 | 功能受限 | 抽象封装层，可回退直接 API |
| SSE 连接断开 | 结果丢失 | 会话持久化 + 重连恢复 |
| Token 消耗过大 | 成本失控 | 缓存机制 + 用量监控 |
| 跨文件分析慢 | 体验差 | 渐进式加载 + 后台预热 |
